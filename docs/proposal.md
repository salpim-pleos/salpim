## 1. 앱 이름 / 한 줄 소개

**살핌 (Salpim)** — 주행 중엔 조용히 지켜보고, 차량 이상이나 점검 시점이 다가오면 정차 후 블루핸즈 안내·예약까지 한 번에 이어 주는 차량 관리 동반 앱

## 2. 기획 배경

> 접수양식 02-2번 칸에 넣은 문안과 같다 (2026-11-09). 출처는 원문·초록을 직접 열어 확인한 것만 썼다.

- **출발점.** 기획자 본인은 차를 잘 모른다. 회사에 있는 차량 정비사에게 종종 도움을 받지만, 그때 들은 설명을 매번 잊어버린다.
- **잘 모르는 분야의 설명은 기억에 잘 남지 않는다.** 같은 글을 읽어도 그 분야 배경지식이 많은 학생이 더 많이 기억하고 오래 유지했으며[1], 다시 접하지 않은 정보는 시간이 지나며 빠르게 잊힌다(망각 곡선)[2]. 그래서 설명을 미리 외우게 하는 대신, 차를 운전하는 바로 그 순간에 차가 알려 주는 편이 낫다.
- **경고의 뜻을 모르는 운전자가 많다.** 미국 운전자 2,000명 조사에서 타이어 공기압 경고등을 알아보지 못한 비율이 49%, 브레이크 시스템 경고등은 46%였다[3]. 국내 자동차 커뮤니티에도 "주유 후 엔진경고등이 켜졌는데 이럴 수도 있나요?" 같은 질문이 올라온다(예시[4]).
- **경고에서 정비까지 흐름이 끊겨 있다.** 경고를 확인한 뒤 정비소 검색, 길 안내, 예약을 운전자가 각각 따로 해야 한다.
- **운전 중 화면 조작은 번거롭고 위험하다.** 미국 도로교통안전국(NHTSA)은 차량 내 기기를 조작할 때 시선을 도로에서 한 번에 2초 이하, 합계 12초 이하로만 떼도록 권고하며[5], Pleos 앱 리뷰 가이드도 운전자 주의 분산을 반려 사유로 명시한다.
- **그래서 음성으로 묻고 듣는다. 다만 음성도 만능은 아니다.** 음성 조작은 시선 부담을 줄이지만 조작 시간이 길어지면 그 이점이 상쇄되었다[6]. 따라서 질문은 짧게, 답은 한 줄로 설계한다.

→ 살핌은 운전자가 미리 외우지 않아도 되도록, 경고가 뜬 순간 쉬운 말 한 줄로 알리고, 운전 중에는 음성으로 묻고 듣게 하며, 정차한 뒤에 자세한 설명과 정비소 안내·예약까지 이어 준다.

## 3. 주요 기능 및 차량 특화 요소

핵심 아이디어: **차량의 주행 상태(주차/정차/주행)를 앱이 직접 인지해서 역할을 바꾼다.** 심사 반려 사유인 "주의 분산"을 설계의 출발점으로 삼았다.

| 상태 | 앱의 역할 | 기능 |
|---|---|---|
| 주행 중 | 꼭 필요한 정보만 큰 글씨로 최대 3개. 입력·스크롤 없음 | 글랜스 |
| 이상 발생 | 경고의 뜻과 긴급도를 한 줄 + 색으로. 터치 불필요 | 경고 해설 |
| 정차·주차 | 경고 상세(원인 후보, 해야 할 일), 정비소 안내, 운전 습관 리포트 | 경고 상세, 정비 연결, 습관 코치 |

1. **차량 이상 해설 (코어)** — 서드파티 앱이 받을 수 있는 Safety 신호를 쉬운 말로 풀어 긴급도(즉시 정차 / 점검 권장 / 안내)와 함께 보여 준다. 설명은 앱 안의 지식 베이스로 **오프라인 동작**하며, 단정하지 않고 "점검 권장" 톤을 유지한다. 모르는 신호는 "알 수 없는 경고, 점검 권장"으로 안전하게 처리한다.
   - 대상 신호 (Vehicle SDK 공개 API, 권한 `CAR_SAFETY`): 엔진오일·브레이크액·변속기오일 레벨(`LOW`/`CRITICALLY_LOW`), 파워다운(엔진 이상) 경고, 워셔액 부족, 안전벨트 미착용, 에어백 전개
   - 계기판 경고등 전체(타이어·ABS 등)는 signature 권한이라 서드파티 앱이 받을 수 없음 → "권한 승인 시 확장"으로 구분 (S2)
2. **점검 시점 예상 (코어, 신규)** — 경고가 뜨기 전에 "곧 점검할 때"를 알려 준다. 누적 주행거리(Odometer API)와 사용자가 입력한 최근 교체 기록으로 소모품별 예상 점검 시점을 계산한다 (예: "엔진오일 교체까지 약 800km"). 기준 주기는 차량 매뉴얼 값을 쓰고, 예상치임을 화면에 명시한다. `[S3: Odometer 메서드 확인]` `[근거 필요: 차종별 매뉴얼 교체 주기]`
3. **블루핸즈 연결 — 안내부터 예약까지 (코어)** — 이상 해설이나 점검 예상 화면에서 바로 다음 행동으로 이어진다.
   - **가까운 블루핸즈 찾기**: 앱 안에 가까운 블루핸즈 목록(거리 포함)을 보여 주고, 고르면 NaviHelper `requestRoute(RouteInfo(...))`로 길 안내한다 (S5)
     - **데이터 출처는 현대가 가진 블루핸즈 정보로 교체하는 것을 전제로 한다** [설계, 2026-11-09 결정]. 블루핸즈 지점 정보와 예약 시스템은 현대가 이미 보유하므로, 앱은 장소 검색을 인터페이스(`NearbyPlaceRepository`)로 분리해 두고 지금은 예시 데이터로 동작한다(화면에 "예시 데이터" 표시). 제휴 시 현대 데이터·예약 API로 이 구현만 바꾸면 된다
     - 외부 지도 API(카카오·네이버)는 쓰지 않는다: 키 발급·네트워크 의존·현재 위치 외부 전송·개인정보 처리 방침 부담에 비해 얻는 것이 적다. 이로써 "개인정보 외부 전송 없음" 원칙을 그대로 지킨다
     - 플랫폼 기능 활용: NaviHelper `requestNavigationScreen(SearchPlace("블루핸즈"))`로 내비 자체 검색 화면을 열 수 있다 (외부 키·위치 전송 불필요)
     - 단골 블루핸즈를 저장해 두면 검색 없이 바로 길 안내
     - 정차·주차 화면에서 사용자가 요청했을 때만 목록을 띄운다 (주의 분산 방지). 음성으로는 주행 중에도 "가장 가까운 곳으로 안내할까요?" 수준으로만
   - **휴대폰으로 예약**: 화면에 공식 정비 예약 페이지로 가는 QR 코드를 띄운다. 운전자는 정차 중에 휴대폰으로 찍어 마이현대/현대 홈페이지에서 예약을 마친다. 현대 순정 인포테인먼트의 차량 관리 화면도 같은 QR 예약 방식을 쓴다. 정비 항목(예: 엔진오일 점검)을 미리 정리해 보여 줘 예약 입력을 줄인다
   - **(향후) 앱 내 예약**: 블루핸즈/마이현대 제휴 API가 열리면 차량 상태와 정비 항목을 담아 앱 안에서 바로 예약. 현재 공개 API는 확인되지 않음
4. **음성으로 모든 조작 (코어, 신규)** — 운전 중에 화면을 만지지 않아도 되도록 모든 기능을 말로 쓸 수 있다. Pleos SpeechToText/TextToSpeech SDK(공개, ON_DEVICE 모드는 키 불필요) 사용.
   - 예: "차 상태 어때?" → "모두 괜찮아요. 엔진오일 교체는 2,400km 남았어요" / "계속 달려도 돼?" / "가까운 블루핸즈 찾아 줘" → "세 곳을 찾았어요. 몇 번째로 갈까요?" → "첫 번째" → 길 안내 / "예약할래" → 예약 QR 화면
   - 답은 소리와 화면 글자로 같이. 앱이 먼저 말하는 건 차량 이상 한 줄뿐, 내비 음성과 겹치지 않게 오디오 포커스 정책 준수 `[확인 필요: Audio Focus 가이드, 시스템 음성 비서·운전대 음성 버튼 연동 가능 여부]`
   - 차를 모르는 사람을 위해 부품 이름에 쉬운 설명을 붙인다 ("엔진오일: 엔진이 잘 돌도록 돕는 기름")
5. **주유 예측과 주유소 안내 (코어, 신규)** — 누적 주행거리와 연료 잔량으로 이 차의 "연료 1%당 km" 기록을 쌓고, 그 분포로 남은 거리를 두 단계로 예측한다.
   - **아마도 갈 수 있는 거리**(지난 주행의 75%를 덮음 = 연비 하위 25% 분위) / **거의 확실한 거리**(90%를 덮음 = 하위 10% 분위)
   - 결정 트리: 잔량 모름 → 표시 안 함 / 거의 확실한 거리 < 40km → 지금 주유 / 거의 확실한 거리 ≥ 목적지+여유 30km → 충분 / 아마도 거리 ≥ 목적지+여유 → 가는 길에 주유 / 그 외 → 지금 주유
   - 기록이 5개 미만이면 기본 연비로 계산하고 정확도가 낮다고 표시
   - 주유가 필요하면 가까운 주유소 목록(블루핸즈와 같은 장소 인터페이스, 현재 예시 데이터) → NaviHelper 길 안내. 음성: "얼마나 더 갈 수 있어?", "가까운 주유소"
   - 데이터: Odometer(`CAR_DRIVE`), Fuel(`CAR_ENERGY`) — 메서드 확인 필요 `[S6]`. 목적지까지 거리는 NaviHelper 경로 정보 `[S5 확인 필요]`
6. **습관 코치 (확장)** — 급가속·급제동·급조향을 검출해 정차 후 점수와 개선 팁 1~2개를 보여 준다. 주행 중에는 짧은 시각 표시만, 소리 없음. Vehicle SDK에 차속 API가 없어 AAOS 표준 `CarPropertyManager` 경로를 확인 중이며, 안 되면 브레이크 페달·앞바퀴 조향각 중심으로 축소한다 `[S3]`
7. **글랜스 (확장)** — 주행 중 "지금 신경 써야 할 것"만 최대 3개: 차량 이상, 다가오는 점검, 오늘의 안전 점수. 속도·RPM처럼 시스템이 이미 보여 주는 정보는 중복하지 않는다.

차량 특화 요소:
- 주행 상태 판정(주차 브레이크·기어·속도)과 `CarUxRestrictions` 주행 제한을 함께 반영해 화면을 자동 전환
- 경고 정보(Safety, Tire), 주행 데이터(Brake, DrivingMode, Steeringwheel), 내비(NaviHelper) 등 차량에서만 얻을 수 있는 신호를 사용
- 주행 중 네트워크 불안정을 전제로 모든 핵심 기능이 오프라인 동작

## 4. 주요 사용 시나리오

**시나리오 A — 주행 중 엔진오일 부족**
1. 고속도로 주행 중 엔진오일 레벨이 `LOW`로 바뀜
2. 앱 화면 상단에 한 줄: "엔진오일이 부족해요. 정차 후 점검을 권장해요" (터치 불필요)
3. 휴게소에 주차하면 상세 화면으로 자동 전환: 가능한 원인, 해야 할 일
4. "블루핸즈로 안내" → 내비 검색 화면에서 가까운 블루핸즈 선택 → 길 안내
5. 또는 "휴대폰으로 예약" → QR 코드를 찍어 마이현대에서 엔진오일 점검 예약

**시나리오 B — 경고 전에 미리 알기**
1. 주차 후 앱이 누적 주행거리로 "엔진오일 교체까지 약 800km"를 표시
2. 이번 주말 일정에 맞춰 QR로 블루핸즈 예약 (예약은 3일 후~6주 이내 가능, 공식 안내 기준)

**시나리오 C — 출근길 운전 습관**
1. 주행 중 급제동 1회 → 점수 칸에 "방금 급제동"이 3초 표시
2. 주차 후 리포트: 오늘 83점, 급제동 1회·급가속 1회, 팁 "앞차와 거리를 조금 더 두면…"

화면 구성 시안: 디자인 캔버스 "살핌 화면 구성" 참고 (주행 기본 / 경고 / 급제동 직후 / 정차 상세)

| NaviHelper (`NAVI_CUSTOM_MAP`, `NAVI_ROUTE_SEARCH`) | 블루핸즈 길 안내, 오프라인 폴백 검색 화면 | API 확인됨 (S5) |
| 장소 데이터 (`NearbyPlaceRepository`) | 블루핸즈·주유소 목록 | 현재 예시 데이터. 제휴 시 현대 블루핸즈 데이터·예약 API로 교체. 외부 지도 API·위치 전송 없음 |
| SpeechToText / TextToSpeech (`TTS_SERVICE` 등) | 음성 명령, 음성 답변 | SDK 공개 확인 (S6), 명령 인식 방식은 구현 시 확인 |
| 사용하지 않음 | ADAS, LLM(오프라인 원칙, 설치 가이드 없음) | — |

권한은 실제 쓰는 것만, 앱 심사 승인 범위 안에서 선언한다 (미승인 권한 선언 시 심사 반려).

### 구조

- 차량 신호는 하나의 인터페이스(SignalSource) 뒤로 격리 → SDK 변경 시 수정 범위가 한 곳. 같은 인터페이스의 시뮬레이션 구현으로 에뮬레이터 없이 테스트·시연 가능 (시뮬레이션 중에는 화면에 항상 SIMULATED 표시)
- 상태머신(디바운스·히스테리시스)으로 정차/주행 경계에서 화면이 깜빡이지 않게 함. 주행 진입은 즉시 제한
- 개인정보 외부 전송 없음, 기록은 기기 안에만 저장하고 앱에서 삭제 가능

## 6. 기대효과 및 발전 가능성

**기대효과**
- 이상 발생 시 운전자가 "지금 무엇을 해야 하는지"를 주행을 방해받지 않고 알 수 있음
- 이상 감지·점검 예상 → 블루핸즈 안내 → 예약까지 한 흐름. 현재는 운전자가 경고를 보고 직접 검색·전화·앱 예약을 따로 해야 함
- 경고 전에 점검 시점을 알려 큰 고장 전에 정비로 연결 (예방 정비)
- 블루핸즈 입장에서는 정비 수요가 미리 예약으로 들어옴 → 제휴 근거
- 운전 습관 피드백으로 급제동·급가속 감소 유도

**사업성**
- 타깃: Pleos Connect 탑재 차량 운전자 전체. 특히 차량 경고에 익숙하지 않은 초보·고령 운전자, 차량 공유/렌터카 이용자
- 예상 MAU / Retention: `[근거 필요: 탑재 차종 판매 대수 × 앱 설치율 가정. 가정치와 출처를 함께 명시]` (적용 차종은 그랜저·아반떼·투싼 등으로 확장 중)
- Retention 근거: 경고는 드물지만 습관 리포트·안전 점수는 매 주행 생성되어 재방문 동기가 됨
- 확장 (모두 "향후"로 서술하고 현재 범위와 구분):
  1. **블루핸즈/마이현대 예약 제휴 API** — 차량 상태·정비 항목을 담아 앱 안에서 바로 예약, 정비 완료 기록을 받아 점검 예상 자동 갱신
  2. 경고등 전체 해설 — 서드파티 권한 승인 시 타이어·ABS 등으로 확대
  3. 보험(운전 습관 연계), 차종별 지식 베이스 확대
