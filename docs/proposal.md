## 1. 앱 이름 / 한 줄 소개

**살핌 (Salpim)** — 운전자가 화면을 들여다보지 않아도 되는, 주행 상태에 따라 역할을 바꾸는 차량 안전 동반 앱

## 2. 기획 배경

- **경고등의 의미를 모르는 불안.** 계기판 경고가 켜졌을 때 운전자는 "지금 바로 서야 하는지, 나중에 점검해도 되는지"를 그 자리에서 판단하기 어렵다. 매뉴얼은 차 안에서 찾아 읽기 어렵고, 주행 중 휴대폰 검색은 위험하다. `[근거 필요: 경고등 인지도 설문/기사]`
- **주행 중 정보 과잉.** 차량 화면의 앱이 늘수록 주의 분산 위험이 커진다. 앱 리뷰 가이드도 운전자 주의 분산을 반려 사유로 명시한다.
- **정비로 이어지지 않는 경고.** 경고를 확인해도 정비소를 찾고 안내를 시작하는 데 여러 단계가 필요하다.

→ 필요한 것: 주행 중에는 조용하고, 꼭 필요할 때 한 줄로 알리고, 정차한 뒤에 자세히 설명하고 다음 행동(정비소 안내)까지 이어 주는 앱.

## 3. 주요 기능 및 차량 특화 요소

핵심 아이디어: **차량의 주행 상태(주차/정차/주행)를 앱이 직접 인지해서 역할을 바꾼다.** 심사 반려 사유인 "주의 분산"을 설계의 출발점으로 삼았다.

| 상태 | 앱의 역할 | 기능 |
|---|---|---|
| 주행 중 | 꼭 필요한 정보만 큰 글씨로 최대 3개. 입력·스크롤 없음 | 글랜스 |
| 이상 발생 | 경고의 뜻과 긴급도를 한 줄 + 색으로. 터치 불필요 | 경고 해설 |
| 정차·주차 | 경고 상세(원인 후보, 해야 할 일), 정비소 안내, 운전 습관 리포트 | 경고 상세, 정비 연결, 습관 코치 |

1. **경고 해설 (코어)** — Safety/Tire API의 경고를 쉬운 말로 풀어 긴급도(즉시 정차 / 점검 권장 / 안내)와 함께 보여 준다. 설명은 앱 안의 지식 베이스로 **오프라인 동작**하며, 단정하지 않고 "점검 권장" 톤을 유지한다. 모르는 경고는 "알 수 없는 경고, 점검 권장"으로 안전하게 처리한다. `[S2: 지원 경고 종류]`
2. **정비 연결 (코어)** — 경고 상세에서 "정비소로 안내" 한 번으로 NaviHelper 목적지를 설정한다. `[S5: POI 검색 가능 여부 → 검색 또는 즐겨찾기 정비소]`
3. **습관 코치** — 속도 변화율로 급가속·급제동을, 조향각으로 급조향을 검출해 정차 후 점수와 개선 팁 1~2개를 보여 준다. 주행 중에는 짧은 시각 표시만, 소리 없음. `[S3: 속도 소스]`
4. **글랜스** — 주행 중 "지금 신경 써야 할 것"만 표시: 활성 경고, 연료/배터리 부족, 오늘의 안전 점수. 속도·RPM처럼 시스템이 이미 보여 주는 정보는 중복하지 않는다.

차량 특화 요소:
- 주행 상태 판정(주차 브레이크·기어·속도)과 `CarUxRestrictions` 주행 제한을 함께 반영해 화면을 자동 전환
- 경고 정보(Safety, Tire), 주행 데이터(Brake, DrivingMode, Steeringwheel), 내비(NaviHelper) 등 차량에서만 얻을 수 있는 신호를 사용
- 주행 중 네트워크 불안정을 전제로 모든 핵심 기능이 오프라인 동작

## 4. 주요 사용 시나리오

**시나리오 A — 주행 중 타이어 공기압 경고**
1. 고속도로 주행 중 타이어 공기압 경고 발생
2. 앱 화면 상단에 노란색 한 줄: "타이어 공기압이 낮아요. 정차 후 확인을 권장해요" (터치 불필요)
3. 휴게소에 주차하면 화면이 자동으로 상세 화면으로 전환: 가능한 원인, 해야 할 일 3단계
4. "정비소로 안내" → 내비 목적지 설정

**시나리오 B — 출근길 운전 습관**
1. 주행 중 급제동 1회 → 점수 칸에 "방금 급제동"이 3초 표시
2. 주차 후 리포트: 오늘 83점, 급제동 1회·급가속 1회, 팁 "앞차와 거리를 조금 더 두면…"

화면 구성 시안: 디자인 캔버스 "살핌 화면 구성" 참고 (주행 기본 / 경고 / 급제동 직후 / 정차 상세)

## 5. 개발 계획

### Pleos 구현 범위와 SDK/API 사용 계획

| SDK/API | 용도 | 상태 |
|---|---|---|
| Vehicle — Safety, Tire | 경고 정보 → 경고 해설 | `[S2]` |
| Vehicle — Brake, DrivingMode | 주차 브레이크·주행 상태 판정 | `[S3]` |
| Vehicle — Steeringwheel | 급조향 검출 | 그룹 존재 확인됨 |
| 속도 소스 (Vehicle SDK 또는 AAOS 표준 프로퍼티) | 주행 판정, 급가속·급제동 | `[S3]` |
| CarUxRestrictionsManager (AAOS 표준) | 주행 제한 반영 | 구현 완료 |
| NaviHelper | 정비소 목적지 설정 | `[S5]` |
| 사용하지 않음 | Fused Location, ADAS (차량 기준 미지원), TTS/STT (공개 전) | — |

권한은 사용하는 도메인만 선언: `CAR_DRIVE`, `CAR_SAFETY` (+ 전기차 배터리 사용 시 `CAR_ENERGY`)

### 구조

- 차량 신호는 하나의 인터페이스(SignalSource) 뒤로 격리 → SDK 변경 시 수정 범위가 한 곳. 같은 인터페이스의 시뮬레이션 구현으로 에뮬레이터 없이 테스트·시연 가능 (시뮬레이션 중에는 화면에 항상 SIMULATED 표시)
- 상태머신(디바운스·히스테리시스)으로 정차/주행 경계에서 화면이 깜빡이지 않게 함. 주행 진입은 즉시 제한
- 개인정보 외부 전송 없음, 기록은 기기 안에만 저장하고 앱에서 삭제 가능

## 6. 기대효과 및 발전 가능성

**기대효과**
- 경고 발생 시 운전자가 "지금 무엇을 해야 하는지"를 주행을 방해받지 않고 알 수 있음
- 경고 → 정비소 안내까지 한 흐름으로 연결
- 운전 습관 피드백으로 급제동·급가속 감소 유도

**사업성**
- 타깃: Pleos Connect 탑재 차량 운전자 전체. 특히 차량 경고에 익숙하지 않은 초보·고령 운전자, 차량 공유/렌터카 이용자
- 예상 MAU / Retention: `[근거 필요: 탑재 차종 판매 대수 × 앱 설치율 가정. 가정치와 출처를 함께 명시]` (적용 차종은 그랜저·아반떼·투싼 등으로 확장 중)
- Retention 근거: 경고는 드물지만 습관 리포트·안전 점수는 매 주행 생성되어 재방문 동기가 됨
- 확장: 정비소 예약 제휴, 보험(운전 습관 연계) 제휴, 경고 지식 베이스의 차종별 확장 — 모두 "향후 확장"으로 서술하고 현재 범위와 구분
